# Oral Cancer Classification — Notebook Documentation

This repository contains one primary notebook:

- **`oral-cancer-efficientnet-b4-model (3).ipynb`** *(legacy filename; notebook content includes DINOv2 and multi-architecture experiments)*

The notebook is a full end-to-end deep learning workflow for **oral cancer image classification**, including data preparation, patient-safe splitting, ROI processing, augmentation, training, evaluation, and result export.

---

## What was done in this notebook

The notebook contains two major experiment tracks:

1. **OralCancerNet v3 (DINOv2 ViT-S/14 + hierarchical heads)**
2. **OralCancerNet multi-architecture pipeline (v4-style block)**

### 1) Data ingestion and harmonization

- Loads and merges:
  - image metadata (`Imagewise_Data.csv`)
  - patient metadata (`Patientwise_Data.csv`)
  - COCO-style annotations (`Annotation.json`)
- Validates cross-source consistency
- Builds patient-aware records
- Handles missing demographics (imputation flags are retained)
- Performs label-noise auditing and diagnosis grouping

### 2) Patient-level leakage-safe split strategy

- Creates **patient-level labels** using severity ranking (`Healthy`, `Benign`, `OPMD`, `OCA`)
- Creates **compound stratification keys** (category + center + noise)
- Splits dataset into **70/15/15** (train/val/test) at patient level
- Adds **5-fold stratified CV setup** on patient groups
- Runs split quality checks and leakage verification

### 3) ROI-based image preprocessing

- Extracts oral cavity and lesion bounding boxes
- Crops and resizes images to model size (DINOv2-compatible)
- Stores processed images and validates on disk
- Computes pixel statistics / normalization artifacts for downstream training

### 4) Labeling and dataset pipeline

- Builds hierarchical labels:
  - 4-class category head
  - binary safe-vs-concerning head
  - sub-heads for safe and concerning branches
- Encodes demographic/tabular features
- Creates PyTorch datasets and dataloaders
- Applies augmentation policies (including CutMix/MixUp variants)

### 5) DINOv2 model design (v3 track)

- Backbone: `dinov2_vits14`
- Hierarchical multi-head architecture with regularization modules
- Phase-aware freeze/unfreeze utilities
- Composite training loss (classification + hierarchical objectives + penalties)

### 6) Phase-based training

- **Phase 1**: frozen backbone, train heads
- **Phase 2**: unfreeze last transformer blocks, fine-tune
- Cosine warmup scheduler, EMA/SWA support, gradient controls
- Checkpointing of best and periodic states
- Training curves and history export

### 7) Comprehensive evaluation

- Test-time inference for direct and hierarchical predictions
- Optional TTA evaluation
- Reports for:
  - 4-class classification
  - binary screening
  - diagnosis-level metrics
  - patient-level aggregation
- Saves confusion matrices, ROC/PR curves, confidence/calibration plots
- Exports prediction CSV/JSON artifacts

### 8) Multi-architecture pipeline block

A second large section in the notebook extends the project to a broader architecture framework with:

- architecture registry/spec abstraction
- model-aware image sizing and augmentations
- phase training engine reuse
- per-model result summaries and plots

## Core configuration seen in notebook

From the DINOv2 configuration blocks:

- Image size: **518 × 518** *(chosen to align with DINOv2 patching: 518 ÷ 14 = 37 patches/side)*
- Patch size: **14**
- Classes: **4** (`Healthy`, `Benign`, `OPMD`, `OCA`)
- Seed: **42**
- Split ratio: **70/15/15**
- Folds: **5**
- TTA enabled (multiple views)
- Two-phase fine-tuning strategy
